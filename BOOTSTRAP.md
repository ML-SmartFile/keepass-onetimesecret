# BOOTSTRAP — verify the machine, do not install

Target: **PC-26-Klaus** (Windows). Run this before M0.

## Your role in this file

**You have no administrator rights and must not install anything.** No winget, no
installers, no `dotnet-install.ps1`, no unpacking archives into `C:\`. Do not ask for an
elevated terminal — the user cannot give you one.

Your job here is to **check what exists and report what is missing**, precisely enough
that the user can install it themselves in one pass. Anything you cannot verify, say so
rather than assuming.

---

## Expected layout

```
C:\KeePass\                    portable KeePass 2.x + test database
  KeePass.exe
  Plugins\                     build output is copied here
  test.kdbx
  test-password.txt

C:\Code\ML-Smartfile\keepass-onetimesecret\    the git repo
```

Projects live under `C:\Code\<github-user-or-org>\<repo>\`. KeePass sits outside that
tree because it is a tool, not a project. Use both paths as given; do not propose
alternatives and do not place KeePass inside the repo.

---

## Checks

Run each, record the result, and do not stop at the first failure — the user wants the
complete gap list in one go.

### 1. Git

`git --version`. Needs any recent version.

### 2. .NET SDK

`dotnet --info`. Needs **SDK 8.0 or newer**. Note every SDK listed, not just the newest.

### 3. KeePass

`C:\KeePass\KeePass.exe` exists; report its file version. Confirm `C:\KeePass\Plugins\`
exists.

### 4. Write access to `C:\KeePass\` — do not skip this

A folder created directly under `C:\` often leaves ordinary users with read-only access,
which would break both the test database and the post-build copy of the plugin DLL.

Verify by actually writing: create `C:\KeePass\Plugins\write-test.tmp`, then delete it.
Report success or the exact error. If it fails, the user needs to grant their own account
**Modify** on `C:\KeePass\` — that is an admin action and belongs in your gap list.

### 5. Reference assemblies

Check whether `Microsoft.NETFramework.ReferenceAssemblies.net472` can be restored from
nuget.org (`dotnet restore` on a scratch project, step 7). This needs no admin rights,
only network access — some corporate networks block or proxy nuget.org.

### 6. Repo

Does `C:\Code\ML-Smartfile\keepass-onetimesecret\` exist, and is it a git repo? Is there
a remote at `ML-Smartfile/keepass-onetimesecret`? Report, do not create the folder tree
yourself beyond `git init` in a folder that already exists.

### 7. Toolchain proof

Only if steps 1–5 pass. In `%TEMP%`, create a scratch project:

- SDK-style `net472` class library
- `Microsoft.NETFramework.ReferenceAssemblies.net472` with `PrivateAssets="all"`
- a reference to `C:\KeePass\KeePass.exe` with `<Private>false</Private>`
- one class deriving from `KeePass.Plugins.Plugin`
- `using System.Windows.Forms;` and a `ToolStripMenuItem` field, to prove WinForms resolves

`dotnet build` must succeed. Delete the scratch project afterwards. This is the single
most valuable check in the file: it proves the no-Visual-Studio build path works before
any real code exists.

> **Why no Visual Studio.** A `net472` library builds under the plain .NET SDK once the
> reference assemblies package is present. That package is build-time only
> (`PrivateAssets="all"`), ships nothing into the plugin, and so does not conflict with
> the no-dependencies rule in `CLAUDE.md`. The .NET Framework 4.x *runtime* is already on
> every supported Windows version, so the built DLL loads in KeePass without anything
> further.
>
> Consequence: there is no WinForms designer. Write all form code by hand — no
> `.Designer.cs` generated by a tool, no `.resx` beyond what you author deliberately.

### 8. Test database

Only once steps 2–4 pass. `C:\KeePass\test.kdbx` should exist with master password
`TestOnly!2026` (also written to `C:\KeePass\test-password.txt`).

KeePass has no CLI for this, so **you can create it yourself** without any installation:
build a throwaway `net472` console project in `%TEMP%` that references
`C:\KeePass\KeePass.exe` and uses `KeePassLib` directly (`PwDatabase.New`,
`CompositeKey` + `KcpPassword`, `PwEntry`, `Save`). Delete the throwaway project
afterwards; it is not part of the repo.

Required contents — M1's acceptance criteria depend on the fourth entry:

| Title | UserName | Password | Notes |
|---|---|---|---|
| `Test Simple` | `alice` | `Simple123!` | short note |
| `Test Umlauts` | `bob@example.at` | `Pässwörd-Ümlaut-ß!` | multiline note with CRLF |
| `Test Long` | `carol` | 64-char random | empty |
| `Test Reference` | `dave` | `{REF:P@I:<uuid of Test Simple>}` | references entry 1 |

Verify by reopening the database and confirming all four entries load.

## Report back

Two tables, then stop.

**What is present:** component, version, path.

**What is missing:** component, exactly what the user must install or change, and where
it must end up. Be specific enough to act on without further research — name the download
page, the target folder, and for the permission fix the exact folder and right needed.

Then wait. **Do not start M0**, and do not attempt a workaround for a missing component.

## Honest limits

- Whether nuget.org is reachable from this network is unknown until step 5 runs. If it is
  blocked, the whole no-Visual-Studio approach needs rethinking — say so plainly rather
  than improvising.
- The KeePass portable download URL changes with each release. Find the current one on
  `keepass.info`; never use a mirror.
